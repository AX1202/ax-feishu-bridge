## 调查：Pi 飞书/Lark 扩展"被屏蔽"问题
- 现象：Pi agent 里已安装的飞书/Lark 扩展加载不到，用户怀疑是配置文件把它屏蔽了。
- 配置文件位置：全局配置 `~/.pi/agent/settings.json` 的 `packages` 数组。
- 根因：`packages` 中飞书扩展注册为本地路径
  `"../../Dev/projects/pi-feishu-lark/.pi/extensions/feishu/index.ts"`
  （相对 `~/.pi/agent` 解析为 `/Users/ax/Dev/projects/pi-feishu-lark/...`）。
  该目录现在存在但**为空**（项目已更名为 `ax-feishu-bridge`），入口文件不存在。
- Pi 加载机制：`package-manager.resolveLocalExtensionSource` 在 `!existsSync(resolved)` 时静默 `return`，
  不报错、不加资源 → 扩展直接不加载，表现成"被屏蔽"。
- 当前可用入口：`/Users/ax/Dev/projects/ax-feishu-bridge/.pi/extensions/feishu/index.ts`（确认存在）。
- 排除项：settings 中没有 `!`/`+`/`-` 排除模式，故 dead path 是唯一原因，不是显式 deny/allowlist。
- 修复方向（待用户确认，尚未改动）：
  1) 把 settings.json 该路径改指向 ax-feishu-bridge（建议用绝对路径，避免再因目录移动失效）；
  2) 或 `pi install local:/Users/ax/Dev/projects/ax-feishu-bridge` 让 Pi 接管；
  3) 或改用已发布包 `pi install npm:ax-feishu-bridge`。

## 已执行：切换 Pi 使用 npm 版 pi-feishu-lark（2026-08-17 17:4x）
- 用户最终决定：**停用本地开发版，改用 npm 拉取的 `pi-feishu-lark` 扩展**。
- 操作：备份 `~/.pi/agent/settings.json` -> `settings.json.bak`；将 `packages` 中第 12 行
  死路径 `"../../Dev/projects/pi-feishu-lark/.pi/extensions/feishu/index.ts"`
  改为 `"npm:pi-feishu-lark"`。
- Pi 的 npm 扩展存储目录为 `~/.pi/agent/npm/node_modules`（之前误看 `~/.pi/agent/extensions` 为空
  是误区，Pi 实际装 npm 包在此处）。
- 注意：`pi-feishu-lark` 当时**尚未**装进 Pi 的 npm 存储（仅在 bun 缓存有 0.2.4），
  改完配置后需让 Pi 安装/加载它（重启 Pi 或 `pi install npm:pi-feishu-lark`），否则不会生效。
- 结论：用户称本地开发目录已"改名为 ax-feishu-bridge"，但 npm 发布包名仍是 `pi-feishu-lark`；
  二者是不同名字，不要混淆。
